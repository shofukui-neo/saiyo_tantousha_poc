# 重複除去アーキテクチャ（2026-07-30 改訂）

「作ったリストに既存企業が混ざる」問題の恒久対策。突合規則と除外マスタの読込を1箇所に固定し、
成果物側からの再検証をゲートにする。

---

## 0. 何が起きていたか（実測）

各ビルダーが**それぞれ別の除外集合**を組んでいたため、経路によって突合するマスタが違った。

| 経路 | 突合していたもの | 抜けていたもの |
|------|------------------|----------------|
| `consolidate-all.js` | 顧客+BALES+SF → `既存被り`列にフラグ | （除外はしない＝設計通り） |
| `format-bales.js`（全成果物の最終ゲート） | 入力の`既存被り`列＋納品台帳 | **マスタと突合し直していない** |
| `build-new-icp-list.js`（完全新規リスト） | consolidated pool＋納品台帳 | **3マスタ全部** |
| `build-icp-fresh-1000.js` | 独自Set（正規化社名のみ） | 農協別称・表記ゆれ・納品台帳 |
| `build-named-mochica-max.js` | 独自Set（社名/法人番号） | 農協別称・表記ゆれ・納品台帳 |
| `dedupe-approach.js` | 禁止+顧客+SF | **BALES既存CRM**・納品台帳 |

マイナビ由来の「完全新規」リストは `既存被り` 列を空で作るため、最終ゲートを**無検証で通過**していた。

納品済み成果物を再突合した結果（2026-07-30）:

## 1. 層の構成

```
company-match.js     … 突合規則（キー生成・MatchIndex）＝唯一の判定ロジック
exclusion-index.js   … 除外マスタの読込（層を選べる）＝唯一のデータ入口
audit-leak.js        … 成果物側からの再突合（納品前ゲート・exit≠0で落とす）
```

除外マスタの層（`buildExclusionIndex({ layers: [...] })`）:

| 層 | 実体 | 意味 |
|----|------|------|
| `customers` | MOCHICA既存顧客（法人名＋LINE登録名） | 既存顧客。どのリストでも絶対除外 |
| `bales` | BALESCLOUD 既存リード22,892 | 既存CRMにいる＝重複架電 |
| `sf` | Salesforce 全リード86,674 | 同上（プリアンブル付きCSVを自動判別） |
| `ledger` | `data/_delivered-ledger.csv` | このツールで過去納品した企業 |
| `pool` | `leads-consolidated-all.csv` | 既知の母集団（「完全新規」判定用・任意） |

省略時は `masters(=customers+bales+sf) + ledger`。マスタが未配置なら `missing` に載せて**警告を出す**
（黙って0件突合にならないようにする）。

## 2. 突合キー（tier）

上から順に判定し、先に当たった段で確定する。`matchDetail()` が `tier` と `一致相手`を返す。

| tier | キー | 内容 |
|------|------|------|
| 法人番号 | 13桁完全一致 | 最優先・誤りなし |
| 社名 | `normCompanyName` | 注釈括弧`【上場】(JA○○)`／法人格／記号／全半角 |
| 農協 | `companyCore` | `JA○○` ⇔ `○○農業協同組合/農協`。**連合会・中央会は別法人なのでcollapseしない** |
| 表記ゆれ | `looseKey` | 旧字体(髙→高)／長音の字種(―－→ー)／カナ⇔かな／支店・拠点／グループ |
| 長音ゆれ | `fuzzyKey` | 長音「ー」の有無を無視（コンピュータ⇔コンピューター）。`--no-fuzzy`で無効化 |

**較正の根拠**（マスタ110,426行・strictユニーク55,925で計測）: strictキーで分離していた
同一法人の別表記が 旧字体30組・長音字種76組・カナ405組・支店等327組。合計848組(1.5%)。
うち別法人の疑いがあるのは長音*削除*のケース（ファミリー/ファミリ、スリーエス/スリーエース）のみ
＝そこだけ最下位tierに隔離し、**除外明細CSVに必ず出す**（silent dropを作らない）。

拠点の扱い: 後株＋拠点名（`ソニー生命保険株式会社柏支社`）は法人格の後ろを丸ごと落として親法人に寄せる。
前株（`株式会社コスモネット本社`）は末尾の拠点語のみ落とす。`ホールディングス/HD`は別法人なので落とさない。

## 3. ゲート（納品前に必ず通る場所）

1. **`format-bales.js`**（BALES取込CSVを作る最終工程）
   - 入力の`既存被り`列を**信用せず**、`customers+bales+sf`と突合し直す
   - 納品台帳・**自己重複**（同一成果物内の同一企業）・**突合キー無し行**も落とす
   - 除外明細を `<out>.excluded.csv` に出す（tier/一致相手つき＝誤爆の目視確認用）
   - 従来動作に戻す: `--no-verify-masters`（非推奨）／`--scope all`は再検証しない
2. **`audit-leak.js`**（成果物CSVを外から検証）
   ```bash
   npm run audit:leak -- data/leads-new-icp-2026-07-30.csv
   npm run audit:leak -- 納品物.csv --ignore-ledger --out data/leak-report.csv
   # 母集団が元々BALES既存リードのリスト（母集団課題ニーズ等）は層を絞って監査
   npm run audit:leak -- data/leads-bales-boshudan.csv --layers customers,ledger
   ```
   被り・自己重複が1件でもあれば **exit 1**。`build-new-icp-list.js` は最後に自動実行する。

## 3.1 実測（フル母集団 `--scope callable`・28,137件）

`既存被り`列（consolidate-all が strict tier で付与済み）に加えて、再検証が新たに落としたもの:

- 既存被り **128件**（SFリード63 / BALES既存57 / MOCHICA顧客8）── すべて tier=表記ゆれ
- 自己重複 **13件**（`(株)ANX`⇔`株式会社ＡＮＸ`、`トナミ国際物流株式会社`⇔`トナミ国際物流(株)` 等）
- 出力 1,389 → **1,248社**。つまり従来は**約10%が被ったまま**渡っていた。

捕まえた例: `(株)日本システムコンサルタント 北海道支社`⇔`株式会社日本システムコンサルタント` /
`(株)メモリードグループ`⇔`株式会社メモリード` / `(株)菜の花`⇔`株式会社菜ノ花` / `高安株式会社`⇔`髙安株式会社` /
`能登わかば農業協同組合【JA能登わかば】`⇔`能登ワカバ農業協同組合`。

## 3.2 既知の限界

1. **法人格の違いは同一視される**（`株式会社光製作所` ⇔ `(有)光製作所`）。`normCompanyName` が法人格を
   一律除去するため。有→株の組織変更が実務上多く、同一視の方が安全と判断（`ng-index.js` の
   前株/後株判定とは別ポリシー）。
2. **グループ名は代表法人に寄る**（`なないろグループ（社福なないろ、(株)EDU…）` ⇔ `社会福祉法人ナナイロ`）。
   グループ一括の窓口は同一の可能性が高いため寄せる。分けたいときは `--no-fuzzy` では効かないので
   除外明細を見て手動で戻す。
3. マスタ側に法人番号列が無い（顧客CSV以外）ため、実運用の突合は**社名系キーが主**。
4. `leads-consolidated-all.csv` の `既存被り` 列は生成時点のスナップショット。マスタを更新したら
   `consolidate-all.js` の再実行が望ましいが、最終ゲートで再検証するので**納品物の安全性は列に依存しない**。

## 4. 運用ルール

- 新しいリスト作成経路を足すときは、除外集合を**自分で組まない**。`buildExclusionIndex()` を呼ぶ。
- 納品前に `npm run audit:leak -- <成果物>` を通す（PASSしないものは渡さない）。
- マスタ（顧客/BALES/SF）を差し替えたら `exclusion-index.js` の `FILES` を更新するだけで全経路に効く。
- 除外明細CSVの `突合tier=長音ゆれ` は誤爆しうる唯一の段。件数が多いときは目視し、必要なら `--no-fuzzy`。
- テスト: `npm run test:dedupe`（78チェック。旧字体/カナ/拠点/連合会ガード/実マスタ突合/衝突監査）
