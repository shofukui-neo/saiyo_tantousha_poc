# 架電禁止リスト 恒久ガード（無条件削除）

架電禁止リストに載っている企業を、**既存・新規を問わずあらゆる成果物から無条件で削除する**仕組み。
「除外し忘れ」を運用の注意力に依存させないため、**出力の関所そのもの**に組み込んである。

---

## 1. 正リスト

| ファイル | 役割 |
|---|---|
| `data/ng-companies.txt` | **正リスト**。1行1社名・UTF-8。ここだけが判定の根拠 |
| `data/ng-source-架電禁止正規化リスト.csv` | 受領した原本（監査用に保管。判定には使わない） |
| `data/ng-sweep-report.csv` | 掃除の明細（どのファイルの誰を消したか） |

現在の登録: **7,191社**（原本 7,301行 → 正規化・重複排除後）。

### 更新のしかた

```bash
npm run ng:sync -- "path/to/新しい禁止リスト.csv"     # 既存にマージ追記
npm run ng:sync -- "path/to/禁止リスト.csv" --replace # 丸ごと置き換え
npm run ng:stat                                       # 現在の登録件数
npm run ng:sweep:apply                                # 追加分を既存成果物から掃除
```

入力はCSV（社名列を自動判定・`--col` で明示可）でも、1行1社名のテキストでも可。
取込時に落とすのは「空」「数字のみ（CSVの壊れ行由来）」だけ。
`株式会社健` `有限会社仁` のような正規化1文字の社名も**登録する**（完全一致でしか当たらないため誤爆しない）。

## 2. 突合ロジック（`src/ng-guard.js`）

キーは `csv.js` の `normCompanyName` と同じ「素の社名」。次の揺れを吸収する。

- 法人格: `株式会社` `(株)` `（株）` `㈱` `有限会社` `医療法人社団` … を除去
- 全角英数・記号・空白・中黒を正規化
- 括弧内の注釈（別称・読み・支店ラベル）を除去
- **旧社名**表記 `（旧：○○）` `（旧社名：○○）` `※旧社名：○○` を展開して両方をキー化
- **半角カナ → 全角カナ**（`ﾋﾞｯｸｶﾒﾗ` = `ビックカメラ`。ng-guard 内部だけの追加正規化）
- **媒体ラベルの末尾除去**（`PICK UP` `急募` `掲載中` `新着` 等）。マイナビ等の一覧から拾った
  社名に混じる掲載ステータス。まず素の表記で照合し、外れたときだけ剥がして再照合する

判定は**完全一致のみ**。部分一致では落とさない（`株式会社ビックカメラ商事` は残る）。

### 前株／後株

既定は**位置を見ない**＝`テスコ株式会社` も `株式会社テスコ` も落とす。
禁止リストの取りこぼしはコンプライアンス事故なので安全側に倒してある
（`exclude-ng.js` 単体の既定とは逆。あちらは「前後逆＝別法人として残す」）。
`NG_STRICT_CORP_POS=1` で位置判定ありに切り替えられる。

## 3. どこで削除されるか（関所）

| 関所 | 効く範囲 |
|---|---|
| `csv.js` `toCsv()` | **src配下のCSV出力ほぼ全て**（約100箇所が経由）。最終防波堤 |
| `master-io.js` `writeMasterCsv()` | 担当者マスタCSV |
| `master-io.js` `writeMasterSheet()` | Googleスプレッドシートへの upsert |
| `monitor/report.js` | 「今アツい企業」ランキング（Markdown・CSV とも、top-N を切る前に除外） |
| `dashboard.js` | 営業ダッシュボードの表示（古い/手編集CSVを読んでも画面に出さない） |
| `clean-csv.js` | CSV修復ユーティリティ（修復ついでに落とす） |

**社名列の自動判定**: `企業名` `会社名` `法人名` `社名` `company_name` と、その接尾
（BALES形式の `会社情報：会社名` など）。社名列が1つも無いCSV（分析レポート等）は素通しする。

削除が起きると標準エラーに出る:

```
🚫 架電禁止 3件を除外（data/leads-bales-callable.csv）: 株式会社◯◯ / △△株式会社 / …
```

### 例外（ガードを外す）

- 除外明細そのものを書く出力 … `toCsv(headers, recs, { ngGuard: false })`
  （`exclude-ng.js` の `.ng-excluded.csv`、`dedupe-approach.js` の除外明細、`ng-sweep-report.csv`）
- 緊急停止 … 環境変数 `NG_GUARD=off`（**通常は使わない**）

## 4. 既存成果物の一括掃除（`npm run ng:sweep`）

ガード導入前に作られたファイルを洗う。CSVと、`data/` 配下のMarkdown表が対象。

```bash
npm run ng:sweep          # ドライラン（何本の何行が消えるか）
npm run ng:sweep:apply    # 実行（元ファイルは *.ng-bak に退避）
```

- BOM・改行コード（CRLF/LF）は元の体裁のまま書き戻す
- Markdownは**表のヘッダから社名列を特定し、その列だけ**を突合する
  （全セルを見ると `NEXT` `東海` のような指標セルが同名の禁止企業に当たって分析表を壊すため）
- 明細は `data/ng-sweep-report.csv`

### 既定で触らないファイル（参照マスタ・原本）

中身を削ると突合や監査ができなくなるので除外している。`--all` で対象に含められる。

- `data/ng-companies.txt` / `data/ng-source-*`（禁止リスト本体・原本）
- `*.ng-excluded.csv` / `ng-sweep-report.csv`（除外明細）
- `BALESCLOUDの既存リスト*` / `MOCHICAの既存顧客リスト*` / `セールスフォース*`（参照マスタ）
- `mochica-customers-*`（受注傾向分析の母集団）

## 6. テスト

```bash
npm run test:ng      # node test/ng-guard.test.js（16件・ネット不要）
```

本番の禁止リストではなくテスト用リストを見せるため、リスト更新でテストが揺れない。
表記ゆれ・半角カナ・旧社名・前株後株・部分一致しないこと・`toCsv` が実際に落とすこと・
`ngGuard:false` の例外・`NG_GUARD=off` の緊急停止までを固定している。

---

## 7. 運用ルール

1. 新しい禁止リストを受領したら `npm run ng:sync -- "<file>"` → `npm run ng:sweep:apply`
2. 納品前に `npm run ng:check`（＝ドライラン）で **0本 / 0行** を確認してから渡す
3. `NG_GUARD=off` は使わない。使うのは「禁止企業の一覧そのものを出す」時だけで、
   その用途は `{ ngGuard: false }` の明示指定で足りる
