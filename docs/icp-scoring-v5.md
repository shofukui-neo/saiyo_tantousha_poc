# ICPスコアリング v5 ── 絶対条件（ゲート）＋2段の期待値モデル

最終更新: 2026-09-01 ／ 実装: [src/icp-rules.js](../src/icp-rules.js)（ゲート）・[src/icp-score-v5.js](../src/icp-score-v5.js)（採点）・[src/mochica-fit.js](../src/mochica-fit.js)（1件採点の入口）
検証: `npm run test:icp`（単体）／ `npm test`（全体に同梱）

v4（6次元の加重和）を廃止し、**接触前に分かることだけで「コールド架電の並び順」を決める**モデルに置き換えた。
点の高低で調整する“軟らかい”嗜好と、母集団から落とす“硬いゲート”を明確に分離している。

---

## 1. 絶対条件（点の高低ではなくゲート）

| 条件 | 内容 | 実装 |
|---|---|---|
| IT・ソフトウェア除外 | 業種ラベルに `ソフトウ/IT/SIer/SES/情報処理/システム開発/受託開発/インターネット/SaaS…` が当たれば **total を12で頭打ち** | `isExcludedIndustry()` |
| エントリー人数 50名以上 | **50名未満と分かっている企業のみ除外。未取得は通す**（架電で聞いて初めて入る値なので、落とすと母集団が全滅する）。`ICP_ENTRY_MIN` で変更可 | `passesEntryFloor()` |
| 官公庁（県庁・市役所系） | **リスト作成・架電・架電リストの3出口をブロック**。外郭（公社・事業団・独法・社協・共済組合）は含まない | `isGovernmentOrg()` |
| DNC / 架電拒否 | −100 | `penalties()` |
| 既存顧客 | −70 | 同上 |
| リスト掲載の資格 | 担当者名あり＋電話番号あり＋新卒6名以上＋従業員100名以上＋非IT＋非官公庁。**採用人数不明は落とさずエンリッチ行き**（`needHire=true`） | `qualifiesForList()` |

規模フロア100名・採用フロア6名は「**判明していて下回るときだけ弾く**」フロアとして維持。
**v4から撤回**: 規模上限2000名の罰・1000名超 −20・競合ATS −45（実測でどちらも全体を上回っていたため）。

3出口のブロックが効く場所:

- リスト作成 … `qualifiesForList()`（`consolidate-all.js` / `build-named-consolidated.js` / `build-new-icp-list.js` の「呼べる条件」列）
- 架電（採点） … `scoreMochica()` が `total=0`・`priority='除外'`・`flags.govExcluded` を返す
- 架電リスト … `format-bales.js` の `want()`（スコープ・オプションを問わず出力しない）

## 2. スコア = 2段の期待値モデル

```
total = 目盛り( p(接触) × p(アポ|接触) )

p(接触)      = 19.6% × 組織型 × 到達性 × 業種 × 規模      ← 母数 8,604架電
p(アポ|接触) = 4.68% × 組織型 × 採用人数                  ← 母数 1,689接触
```

### 第1段（受付を通るか）

| 軸 | 係数 |
|---|---|
| 組織型 | 公的・協同組合系 ×1.67 ／ 民間 ×0.84 |
| 到達性 | C90+（電話妥当＋担当者名）×1.05 ／ C70-89 ×0.60 ／ C50-69 ×0.37 ／ C50未満 ×0.15 |
| 業種 | 負リフト群（IT・建設・機械・不動産・情報処理）×0.83 ／ それ以外 ×1.06 |
| 規模 | 500-1000 ×1.18 ／ 1000+ ×1.12 ／ 300-500 ×0.96 ／ 100-300 ×0.82 ／ 100未満 ×0.86 ／ 不明 ×1.00 |

正リフトは**全部中立化**した。SFの“勝ち業種”は温かいリードの代理変数であって、コールド架電の並べ替えには効かない。

### 第2段（通った先でアポになるか）

| 軸 | 係数 |
|---|---|
| 組織型 | 公的・協同組合系 ×1.29 ／ 民間 ×0.86 |
| 年間新卒採用人数 | 21名+ ×1.50 ／ 11-20名 ×1.04 ／ 6-10名 ×0.77 ／ 5名以下 ×0.65 ／ 不明 ×0.93 |

**分岐点は6名ではなく21名。**

### 段に入れないもの（意図的な不採用）

- **業種は第2段に入れない** … 31業種中29業種が判定不能。
- **規模も第2段に入れない** … 単調にならない。
- **架電メモ由来の入力（新卒有無・利用媒体・検討時期）はどちらの段にも入れない** … 「話が通った会社ほど点が高い」循環になり、コールド架電の順番を決める役に立たないため。
  ただし捨てずに `hot_signals` として残し、**追いかけはICP順の上に固定**する（`flags.hot` / `hotSignals` / `sortKey()`）。

### 目盛り

期待アポ率 0.05%→0点 ／ 0.15%→40点 ／ 0.44%→70点 ／ 3.0%→100点（log線形で内挿）。
**70点＝「今週架電」の帯。モデルを変えても帯は動かさない**（運用の意味を固定するため）。

## 3. 組織型の定義（最大の効き）

JA・厚生連 ／ 協同組合・共済 ／ 非営利法人 ／ 協同組織金融（信金・信組・労金）／ 公共・外郭 = **公的・協同組合系**、それ以外が民間。
**社名から判定する**（業種ラベルは欠損84%のため）。実測で接触率2.1倍・アポ率4.4倍。

`classifyOrgType()` は `{type:'public'|'private', label}` を返し、第1段と第2段の**両方に入る唯一の共通係数**。
なお官公庁（県庁・市役所系）はこの厚遇の対象ではなくブロック対象。外郭団体はブロックせず公的側として扱う。

## 4. 実測での裏取り（捕捉曲線）

| 並べ方 | 上位10% | 上位30% | 上位50% |
|---|---|---|---|
| v4（加重和） | 29% | 53% | 73% |
| v5 | 28% | 56% | 75% |

70点未満 1,303架電でアポ2件（v4は2,175架電で6件）＝**帯の下側に取りこぼしなし**。

### 本リポジトリの統合マスタに当てた結果（2026-09-01・30,290社）

| 帯 | v4（CSV保存値） | v5 |
|---|---|---|
| ◎ 70+（今週架電） | 14,149社 | **7,617社** |
| ○ 50-69 | 7,734社 | 8,944社 |
| △ -49 | 8,407社 | 13,729社 |

ゲート発火: 官公庁125社 ／ エントリー50名未満 0社 ／ IT頭打ち143社。公的・協同組合系は2,256社。
v5上位は信金・信組・JA・厚生連・学校法人・社福が占め、v4で水増しされていた「今週架電」帯が半減した。

## 5. 注意点

1. **エントリー50名の必須条件はコードにしかない**（`ICP_ENTRY_MIN`）。ICP定義側のドキュメントには未追記。
2. **第2段の唯一の軸である採用人数が欠損しやすい**。エントリー人数に至っては本リポジトリの統合マスタで**該当列そのものが無く、ゲート発火0社**。ヒアリング回収が進むまで、この2条件は実質ほとんど効いていない（＝現状のスコア差は主に組織型・到達性・規模で説明される）。
3. `dims.*`（INT/FUNNEL/SIZE/REACH/TIM/TRUST）と `getWeights()` は**v4遺産で、総合点には入らない**。CSV可視化・診断用に残置している。並べ替えの根拠として読まないこと。
