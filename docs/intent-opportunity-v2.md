## 根拠と誤検知対策

- 追加8軸はHTTP(S)の根拠URLと本文が必要。同じ文に新卒・学生などの文脈がある場合に検知する。
- 他社事例・一般論・解決済み・否定の表現を除く。未知の言い回しを含めた完全な意味判定ではないため、引用を確認して利用する。
- 発生日ありの強度は0.9、検討・予定などの表現は0.7。発生日不明は0.4に抑え、その旨を出力する。
- 未来日・無効日・4半減期より古い追加シグナルは採用しない。発生日が分かる根拠は発生日から減衰する。
- ページ全体の最終更新日や求人の取得日を、課題の発生日と同一視しない。
- 発生日不明の同一URL・引用を再取得しても、観測台帳内の最初の根拠確認日から減衰する。
- 同じシグナルは複数資料で見つかっても1回だけ加点。追加軸の課題群ごとに32・32・24・40点の上限を設ける。
- 求人は会社名を正規化した完全一致のみ。社名の部分一致によるグループ会社混入を防ぐ。

## MOCHCA適合と順位

既存 `icp-rules.js` の業種・官公庁・規模・採用・エントリー人数条件を使用する。
既知の条件未達、DNC・架電拒否・除外フラグ・既存顧客は「対象外」で総合優先度0、推奨アクションは架電不可。
架電禁止正規化リストの企業は処理前に除き、CSV・レポートに掲載しない。

業種・従業員数・新卒採用数が不明な企業は「要確認」。採用人数の範囲を数字の連結で誤変換しない。
採用数は最新の実績系列、年間新卒採用人数、採用予定人数の順に採用する。
エントリー人数が不明なら既存ルールどおり除外しないが、要確認項目として残す。

`総合優先度 = インテントスコア × 0.65 + アポ期待度 × 0.35`。
アポ期待度が未取得なら中立値50を使用し、欠損を明示する。適合が「要確認」の企業は最大49点。
従来の `combineWithFit()` は互換用に残すが、CLIはv2の順位を使用する。
インテント階層A〜Dはシグナルの強さを示す。架電可否はMOCHCA適合判定と推奨アクションで確認する。

**これは検証前の営業仮説による優先度で、受注確率（%）ではない。**
重み・合成比率の妥当性と受注率向上は、後日の接触・商談・受注実績で検証する必要がある。

## 実行方法

```powershell
# 既存CSVの情報だけで確認。別ファイル出力と台帳非更新で既存成果物を保持
node src/intent-analyze.js --offline --no-store --out data/leads-intent-v2-offline.csv --report data/intent-v2-offline.md

# 既存の収集経路で本文も取得して16軸を評価
npm run intent:full

# 適合が確認できた企業だけに絞る（欠損企業は出力対象外）
node src/intent-analyze.js --sources csv,mynavi,site --qualified-only --out data/leads-intent-v2-qualified.csv --report data/intent-v2-qualified.md

# 上位100社へ人事求人の分析を追加
npm run intent:jobs

# 既存・追加シグナルとCSV→CLI→レポートをオフライン検証
npm run test:intent
```

追加8軸は `csv`・`mynavi`・`site`・`jobs` が収集した `インテント資料` を共通処理する。
既存リストに本文が保存されていない場合、オフライン再採点だけでは追加軸の新しい根拠は取得できない。
`--no-store` は台帳を更新せず、今回収集できた根拠だけで採点する。継続監視は同オプションを外す。

CSVへ根拠を追加する場合は次のいずれかを使う。

| 入力列 | 値 |
|---|---|
| インテント本文 | 対象企業自身の公開記載。例: 新卒の応募者情報をExcelで管理しています |
| インテント根拠URL | 当該記載を確認したページのURL |
| インテント発生日 | 当該課題・取り組みの日付。YYYY-MM-DD。不明なら空欄 |
| インテント資料JSON | 複数資料の場合 `[{"text":"…","url":"https://…","date":"2026-09-09","source":"csv"}]` |

出力には全16軸、適合判定と理由、要確認項目、提案ルート、根拠URL一覧、シグナル内訳JSON、根拠資料JSONを保持する。
ATS状態・既存被り・採用数・除外フラグも再採点時に保持する。
`icp:ats:intent` の詳細CSVにも16軸と根拠を引き継ぐ。同コマンドは従来どおりATS未導入企業に限定する。

## 利用範囲

適合条件の出所はリポジトリ内の `docs/icp-scoring-v5.md` と `src/icp-rules.js`。
分析対象は入力リストと指定した取得経路の情報に限る。追加8軸に根拠資料がない企業は「未検知」であり、課題がないとは断定できない。
市場全体の発見件数増加や受注率の改善を、この実装とオフラインテストだけで実証したものではない。
