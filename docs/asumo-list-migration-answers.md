## 0. 先に言うべき3点（回答の前提が変わるもの）

### ① P4 は「新モジュール」ではない。asumo が見つけた罠と**同じ罠**を poc も踏んでいた

asumo `call-memo-infer.ts:187-194` の指摘（ヒアリングシートの見出し列を素通しすると母集団タグが
アポ架電で埋まる）は、poc [boshudan-needs.js:87-90](../src/boshudan-needs.js) の
`isUntouchedTemplate` と**同一の現象**である。poc 側の実装：

```js
const TEMPLATE_OPTIONS = ['歩留まり改善','工数削減','一元管理','LINEの利用','コストカット','母集団形成','その他'];
const isUntouchedTemplate = (s) => TEMPLATE_OPTIONS.filter((o) => String(s||'').includes(o)).length >= 6;
```

7項目中**6つ以上が残っていたら未編集テンプレ**＝「母集団形成を選んだ」ことにしない。
→ **P4 は「既存 `call-memo-infer.ts` への規則追加」に格下げ**する。poc から持ち込む価値があるのは
テンプレガード以外の3層（充足規則・中途ガード・自社プロダクトガード）と強/中の2段階。

### ② Playwright 系の収穫は robots.txt を機械判定していない（法務の指摘は正しい）

- `polite.js` 経由の取得は **robots を必ず見る**（disallow は `blocked` で取得しない）。実測で
  106媒体中 disallow は **0件**。
- **[scrape-base.js](../src/scrape-base.js) / [scrape-mynavi.js](../src/scrape-mynavi.js) は robots 判定コードを持たない。**
  ヘッダに「robots は各媒体実装側で尊重」とあるが、実装側に判定が無い。マイナビの利用規約も未確認。
- → **P3 の feeder は、当面「自社採用ページ hop（polite経由・robots遵守）」由来に限定すべき**。
  マイナビ由来は規約確認が済むまで別扱いにする。asumo 側の汚染懸念は正当。

### ③ fuzzy（長音ゆれ）tier は、現母集団で**1件も効いていない**

本日 28,137件 × マスタ56,165社で再実行した結果、tier別の内訳は **社名83 / 表記ゆれ30 / 長音ゆれ0**。
→ asumo は fuzzy を `weak` に落とすどころか、**初期は実装しなくても実害ゼロ**。誤って架電禁止にする
リスクを取る理由が現時点では無い。

### A3. ガード3種の正確な条件

**(a) 農協の連合会/中央会は collapse しない** — `companyCore()` の冒頭2行：

```js
const s = normCompanyName(name);
if (!s) return '';
if (/連合会|中央会/.test(s)) return '';   // 信連/経済連/共済連/厚生連/中央会 は別法人
let core = s, isCoop = false;
if (/農業協同組合$/.test(core)) { core = core.replace(/農業協同組合$/,''); isCoop = true; }
else if (/農協$/.test(core))    { core = core.replace(/農協$/,'');       isCoop = true; }
if (/^ja/.test(core))           { core = core.replace(/^ja/,'');          isCoop = true; }
core = core.trim();
if (!isCoop || core.length < 2) return '';
return 'coop:' + core;
```

**(b) ホールディングス/HD は別法人** — これは「**除去対象に入れていない**」ことで担保している。
`looseKey()` が末尾から落とすのは `(グループ|ぐるーぷ)$` **のみ**。HD/ホールディングスを落とす
コードは存在しない。asumo 側で追加のガードは不要だが、**テストで凍結すること**（誰かが
「ホールディングスも落とそう」と足すのを止めるため）。

**(c) 1文字キーは作らない** — 3箇所すべてに入っている：

```js
// companyCore: if (!isCoop || core.length < 2) return '';
// looseKey:    if (s.length < 2) return '';          // 1文字キーは衝突源なので使わない
// fuzzyKey:    return s.length >= 2 ? s : '';
```

### A4. 旧字体の対応表の実体

**自前テーブル（46字）。ライブラリ非依存・Unicode正規化では代替できない。**
NFKC は `髙`→`高` を行わない（互換文字ではなく異体字のため）。テーブル全体：

```js
const OLD_TO_NEW = {
  髙:'高', 﨑:'崎', 濵:'浜', 濱:'浜', 德:'徳', 嶋:'島', 嵜:'崎', 眞:'真', 瀨:'瀬', 瀧:'滝',
  邊:'辺', 邉:'辺', 齋:'斎', 齊:'斉', 國:'国', 學:'学', 會:'会', 廣:'広', 澤:'沢', 曾:'曽',
  寳:'宝', 龍:'竜', 藪:'薮', 桒:'桑', 槗:'橋', 圓:'円', 惠:'恵', 榮:'栄', 豐:'豊', 淸:'清',
  眗:'晃', 舘:'館', 冨:'富', 籔:'薮', 珎:'珍', 竈:'釜',
};
```

同じ節に**長音・ダッシュ類の字種統一**もある（こちらは正規化順序に注意が要る）：

```js
const DASH_RE = /[―‐–—－‒﹣ｰ~～〜]/g;
const unifyDash = (s) => String(s||'').replace(DASH_RE, 'ー');
```

> ⚠ **順序の落とし穴**: `normCompanyName` は `-‐－―` を記号として**削除**する。
> よって `unifyDash` は**正規化より前**に掛けないと、`ソニ―` が `そに` に潰れて別キーになる。
> `looseKey` は `normCompanyName(stripBranch(unifyDash(name)))` の順で呼んでいる。ここを崩さないこと。

## 🟡 C. 設計が変わるもの（10〜16）

### C1. tier ごとの「統合してよい強さ」— poc 推奨

poc は「除外（落とす）」しかしないので統合の強度概念を持たない。asumo の3段に割り当てるなら：

| tier | asumo 推奨 | 根拠 |
|---|---|---|
| 法人番号 | `exact` | 誤りなし |
| 社名（strict） | **除外判定＝当てる／統合＝`weak`（現行 k4 のまま）** | asumo の「同名他社がありうる」判断のほうが正しい。poc は同名他社の実害に遭っていないだけ |
| 農協コア | `strong` | 連合会/中央会ガードがあるため安全。596キーと小さい |
| 表記ゆれ（tier4） | `strong` | 実測30件すべて正しい。支店・グループ・カナ・旧字体 |
| 長音ゆれ（tier5） | **`weak`、または実装しない** | 実測0件。別法人衝突の実例が2組ある唯一の段 |

**原則**: 除外判定は保守的（当てる）、統合は保守的（当てない）——asumo `lib/prospect/exclusion.ts` の
コメント「架電禁止先に架電した損失のほうが桁違いに大きい」がそのまま tier 設計にも当てはまる。

### C2. 支店/拠点の語彙と、拠点別リードの扱い

語彙（`BRANCH_WORD`）:
```
支社|支店|営業所|営業部|営業本部|本社|本店|本部|事業部|事業所|支部|出張所|工場
```
除去規則は2通り:
- **後株＋拠点名**（`ソニー生命保険株式会社柏支社`）→ 法人格の後ろを**丸ごと**落とす
- **前株/法人格なし**（`株式会社コスモネット本社`）→ 末尾の拠点語（＋直前の都道府県名）を最大3回反復除去

**poc の運用は「親法人に寄せる（同一視）」。** 理由は MOCHICA の契約主体が本社人事で、支店ごとに
別契約しないため。**拠点ごとに採用担当が違うケースは poc では扱っていない。**

→ asumo が拠点別リードを持ちたいなら、**寄せるのを「除外判定」だけに限り、統合（マージ）には
使わない**。`〇〇工業 東京支店` と `〇〇工業` を別 `customers` として持ちつつ、
除外台帳照合では同一視する——これは tier を「除外用」と「統合用」で別に持てば表現できる。

### C3. audit-leak.js の検出定義

| 項目 | 仕様 |
|---|---|
| 既定 layers | `customers,bales,sf,ledger`（`--layers` で指定・`--pool` で母集団 pool も） |
| 判定 tier | company-match の全5段。`--no-fuzzy` で tier5 無効 |
| 検出4種 | ① マスタ被り ② 台帳被り ③ 自己重複 ④ 突合キー無し行 |
| exit code | **①②③が1件でもあれば 1**。`--report-only` で 0。**④はexitに影響しない**（警告のみ） |
| レポート列 | `ファイル, 行, 企業名, 種別, 一致マスタ, 突合tier, 一致相手` |

**CSV形式そのものへの要求は無い。asumo は DB に持ってよい。**
必須なのは1点だけ——**`突合tier` と `一致相手` を必ず残すこと**。これが無いと
「表記ゆれで誤爆したのか、正しく当たったのか」を人が判定できず、silent drop になる。

### C4. feeder CSV は誰がいつ生成するか

**手動。** 人が `npm run mynavi:1000` / `node src/harvest-all-media.js` 等を回す。定期実行はしていない
（Playwright が要るので手元PC限定）。

`discovered_at` には **`取得日` 列（＝スクレイプした日）** を入れる。出力日（CSVを書き出した日）は
別物なので、必要なら asumo の `import_batches` 側で持つ。再開型のハーベスタなので、
1つのCSVに**取得日が異なる行が混在する**——行ごとの `取得日` を使うこと（ファイル日時を使わない）。

### C5. isNonPersonWord の語彙と、二重ゲートの可否

語彙は6群（[src/jp-names.js](../src/jp-names.js) `NON_PERSON_WORDS`）:

| 群 | 語 |
|---|---|
| 採用/選考プロセス | 面接・選考・応募・採用・説明会・エントリー 等 |
| 書類 | 申込書・履歴書・エントリーシート・験申込書 等 |
| 庶務 | 案内・手続・詳細・内容・条件・実施・予定・結果・通知・合格 |
| 役職・職階 | 次長・課長・部長・係長・室長・本部長・局長・主事・主幹・参事・補佐・技監 |
| 連絡先ラベル | 電話・番号・内線・直通・郵便・住所・所在・時間・メール・ダイヤル |
| 職能・組織・人物カテゴリ | 人材・人財・事務・委員・職員・社員・従業・職種・職務・求職・志願・開発 |

**二重ゲートを推奨する。** ただし asumo 側は**落とすのではなく保留**にする：

> asumo 側で `isNonPersonWord` に当たったら、行を捨てずに `contacts.status = 'unknown'` で入れる。

理由：poc が古い版を出す可能性はあるので二重に掛ける価値があるが、二重で「落とす」と
正しい氏名を失ったことが誰にも見えない。保留なら安全側かつ復旧可能。

### C6. 姓名分割は poc 側にあるか

**2つある。**

| 実装 | 方式 | 用途 |
|---|---|---|
| `format-bales.js` の `splitName` | 空白区切りのみ（空白が無ければ全体を姓） | BALES 266列出力用 |
| **`jp-names.js` の `splitName`** | **姓辞書ベース**（空白が無くても分割できる） | 氏名判定の本体 |

→ **feeder では `jp-names.splitName` で分割した `姓` / `名` を poc 側で出す**のが良い。
規則が1つになり、asumo は受け取った値をそのまま `contacts.lastName` / `firstName` へ入れられる。
原文（`採用担当者名`）も併せて渡し、asumo は `displayName` に入れる。

### C7. 「成熟した卒年サイト」の判定基準

**poc に数値閾値は無い（運用知のみ）。** 実測は 27卒 28.3% / 28卒 4.8%。
卒年サイトは前年6月頃に開くが、**問合せ先（＝氏名）は掲載企業が採用広報を本格化させる秋以降に埋まる**。

実装可能な形にするなら：

> **本走の前に、同一キーワードで100社サンプルし、氏名取得率が15%を下回る卒年サイトは使わない。**

これなら時期の勘に依存しない。poc 側で `--target 100 --max-scrape 100` を先に回せば測れる。
