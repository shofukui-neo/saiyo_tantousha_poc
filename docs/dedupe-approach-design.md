# リスト重複照合・クレンジング 設計書（被りなしリスト生成）

> ステータス: **実装済み（2026-07-06）**
> 実装物: [src/dedupe-approach.js](../src/dedupe-approach.js) ／ [src/ng-index.js](../src/ng-index.js)（禁止リスト索引・共有部品）
> npm: `dedupe` ／ 突合基盤: [src/csv.js](../src/csv.js)（`normCorpNumber` / `normCompanyName`）

---

## 0. 目的（先に要点）

「作成したリスト」（母集団）から、**3つの照合対象リスト**に載っている企業を除外し、
**被りのない＝アプローチ可能な純新規リスト**を1本にまとめて生成する。

- 既存の名寄せ基盤（`csv.js`）・禁止照合（`exclude-ng.js`）・SF突合（`sf-merge.js`）を**破壊せず再利用**。
- 禁止照合ロジックは `ng-index.js` に切り出して `exclude-ng.js` と共用（重複実装を排除）。
- **元ファイルは変更しない**（新規2ファイルを書き出すだけのドライラン安全設計）。

---

## 1. 入力

| 種別 | 既定の実体 | 形式 | 突合キー |
|------|-----------|------|----------|
| 母集団（作成したリスト） | `leads-mochica-named-consolidated.csv`（1,902件） | CSV（`企業名`＋`法人番号`列） | 法人番号→社名 |
| ① アプローチ禁止リスト | `data/アプローチ禁止企業一覧.txt`（7,070ユニーク社名） | テキスト・社名のみ・旧社名括弧付き | **社名のみ** |
| ② MOCHICA既存顧客リスト | `data/existing-bango.json`（法人番号1,387件）or 名前付きCSV | JSON配列 / CSV | 法人番号（CSVなら＋社名） |
| ③ MOCHICA SFリードリスト | SFエクスポートCSV（`Company`,`CorporateNumber__c`,`Status`,`Owner`）| CSV | 法人番号→社名 |

- 存在しない/未指定のソースは**警告のうえスキップ**（禁止だけ・既存だけでも動く）。
- ②③は後日ファイルを差し込むだけ（`--customers` / `--sf` にパス指定）。

## 2. 出力

| 出力 | 既定パス | 内容 |
|------|---------|------|
| 被りなしリスト | `<list>-clean.csv` | 3リストのどれにも当たらない純新規のみ・**元の全列を維持** |
| 除外明細 | `<list>-excluded.csv` | 除外された企業＋`除外理由`/`一致リスト`/`突合確度`/`一致キー`＋SF3列 |
| サマリ | 標準出力 | 母集団件数・法人番号充足率・ソース別一致・重複率・残存件数 |

いずれも **BOM+CRLF**（Excel日本語の文字化け回避、`sf-merge.js`/`exclude-ng.js` と同一流儀）。

---

## 3. 突合ロジック（`csv.js` 基盤と完全同一）

1. **法人番号（13桁）一致 → 確度「確実」**（最優先）
2. 無ければ **正規化社名一致 → 確度「推定」**（株式会社・全半角・記号・空白の揺れを吸収）
3. 禁止リストのみ社名一致。加えて `ng-index.js` が **旧社名**（`（旧：〇〇）`）展開と
   **前株/後株**の別法人判定を行う（`テスコ株式会社` ⇔ `株式会社テスコ` は別法人として残す）。

**代表理由の優先順位**: 1件が複数リストに当たった場合、`除外理由`は
**禁止 ＞ 既存顧客 ＞ SFリード** の順で1つを採用（最も強い制約＝禁止を優先）。
当たった全ソースは `一致リスト` 列に併記する（監査用）。

---

## 4. 使い方

```bash
# 既定（母集団＝named-consolidated、既存＝法人番号JSON、SF＝実エクスポート）
npm run dedupe

# 個別指定（後日、名前付き既存顧客CSV／実SFエクスポートが来たら差し替え）
node src/dedupe-approach.js \
  --list leads-mochica-named-consolidated.csv \
  --ng   "data/アプローチ禁止企業一覧.txt" \
  --customers data/mochica-existing-customers.csv \
  --sf   sources/SF-leads.csv \
  --out       leads-clean.csv \
  --out-excluded leads-excluded.csv
```

主なオプション: `--name-col`（既定`企業名`）/ `--corp-col`（既定`法人番号`）。

## 5. 検証結果（2026-07-06・暫定データ）

暫定入力（禁止リスト＋既存法人番号JSON＋SFサンプル4件）での実行:

## 6. 既知の制約・改善余地

1. **母集団の法人番号充足率が 6.4%（122/1,902件）** と低い。既存顧客照合は
   `existing-bango.json` が**法人番号のみ**のため、番号を持たない大多数の行を取りこぼす。
   → **社名入りの既存顧客CSV**（`--customers` にCSV指定）にすれば社名フォールバックが効き、
   検出率が大きく向上する。SFリードも同様に社名列があれば番号なしでも突合可能。
2. SFエクスポートの列名は組織ロケール依存。`Company`/`会社名`, `CorporateNumber__c`/`法人番号`,
   `Status`/`リード状態`, `Owner.Name`/`所有者` の代表候補を自動判定する（想定外は要追記）。
3. 社名一致（推定）は同名異企業を巻き込む可能性がある。禁止リストは前株/後株で緩和済みだが、
   既存顧客/SFの社名一致分は `除外明細` の `突合確度=推定` を目視確認できるようにしてある。
