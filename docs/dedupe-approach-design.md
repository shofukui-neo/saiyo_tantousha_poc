# リスト重複照合・クレンジング 設計書（被りなしリスト生成）

> ステータス: **実装済み（2026-07-06）**
> 実装物: [src/dedupe-approach.js](../src/dedupe-approach.js) ／ [src/ng-index.js](../src/ng-index.js)（禁止リスト索引・共有部品）
> npm: `dedupe` ／ 突合基盤: [src/csv.js](../src/csv.js)（`normCorpNumber` / `normCompanyName`）

---

## 0. 目的（先に要点）

「作成したリスト」（母集団）から、**3つの照合対象リスト**に載っている企業を除外し、
**被りのない＝アプローチ可能な純新規リスト**を1本にまとめて生成する。

- 既存の名寄せ基盤（`csv.js`）・禁止照合（`exclude-ng.js`）・SF突合（`sf-merge.js`）を**破壊せず再利用**。
- 禁止照合ロジックは `ng-index.js` に切り出して `exclude-ng.js` と共用（重複実装を排除）。
- **元ファイルは変更しない**（新規2ファイルを書き出すだけのドライラン安全設計）。

---

## 1. 入力

| 種別 | 実体 | 形式 | 突合キー |
|------|-----------|------|----------|
| 母集団（作成したリスト） | `leads-mochica-named-consolidated.csv`（1,902件） | CSV（`企業名`＋`法人番号`列） | 法人番号→社名 |
| ① アプローチ禁止リスト | `data/アプローチ禁止企業一覧.txt`（7,070ユニーク社名） | テキスト・社名のみ・旧社名括弧付き | **社名のみ** |
| ② MOCHICA既存顧客リスト | `data/MOCHICAの既存顧客リスト - mochica-companies-list.csv`（`法人名`428社）＋任意で `data/existing-bango.json`（法人番号1,387件） | CSV / JSON配列（カンマ区切りで合算可） | 社名（JSONは法人番号） |
| ③ MOCHICA SFリードリスト | `data/セールスフォースMOCHICA参照 - 全てのリードSitoke突合用.csv`（86,673件） | SFレポートCSV（先頭にメタ5行・会社名列=`会社名 / 取引先`・法人番号なし） | **社名のみ** |

- 存在しない/未指定のソースは**警告のうえスキップ**（禁止だけ・既存だけでも動く）。
- 列名の表記揺れ（`会社名 / 取引先`, `法人名`, `リード 状況`）と、SFレポート先頭のメタ行（タイトル/生成日時/検索条件）・末尾の集計行は**自動吸収**する。
- 既存顧客・SFとも実データに**法人番号列が無い**ため、実運用の突合は**社名一致（推定）が主**。同名異企業の巻き込み確認のため `除外明細` に確度と一致キーを残す。

## 2. 出力

| 出力 | 既定パス | 内容 |
|------|---------|------|
| 被りなしリスト | `<list>-clean.csv` | 3リストのどれにも当たらない純新規のみ・**元の全列を維持** |
| 除外明細 | `<list>-excluded.csv` | 除外された企業＋`除外理由`/`一致リスト`/`突合確度`/`一致キー`＋SF3列 |
| サマリ | 標準出力 | 母集団件数・法人番号充足率・ソース別一致・重複率・残存件数 |

いずれも **BOM+CRLF**（Excel日本語の文字化け回避、`sf-merge.js`/`exclude-ng.js` と同一流儀）。

---

## 3. 突合ロジック（`company-match.js` と完全同一）

1. **法人番号（13桁）一致 → 確度「確実」**（最優先）
2. 無ければ **社名系キー一致 → 確度は当たった tier 名**
   （正規化社名 / 農協コア / 表記ゆれ / 長音ゆれ。定義は [dedupe-architecture.md](dedupe-architecture.md#2-突合キーtier)）
3. 禁止リストのみ社名一致。加えて `ng-index.js` が **旧社名**（`（旧：〇〇）`）展開と
   **前株/後株**の別法人判定を行う（`テスコ株式会社` ⇔ `株式会社テスコ` は別法人として残す）。

**照合ソースは5系統**（2026-07-30 に④⑤を追加。実測で被りの最大発生源は**BALES既存CRM**だった）:
① 禁止 ② 既存顧客 ③ SFリード ④ BALES既存CRM ⑤ 納品済み台帳（④⑤は `--no-bales` で無効化）。

**代表理由の優先順位**: 1件が複数リストに当たった場合、`除外理由`は
**禁止 ＞ 既存顧客 ＞ BALES既存 ＞ SFリード ＞ 納品済み** の順で1つを採用（最も強い制約＝禁止を優先）。
当たった全ソースは `一致リスト` 列に併記する（監査用）。

---

## 4. 使い方

```bash
# 既定（母集団＝named-consolidated、既存＝法人番号JSON、SF＝実エクスポート）
npm run dedupe

# 個別指定（後日、名前付き既存顧客CSV／実SFエクスポートが来たら差し替え）
node src/dedupe-approach.js \
  --list leads-mochica-named-consolidated.csv \
  --ng   "data/アプローチ禁止企業一覧.txt" \
  --customers data/mochica-existing-customers.csv \
  --sf   sources/SF-leads.csv \
  --out       leads-clean.csv \
  --out-excluded leads-excluded.csv
```

主なオプション: `--name-col`（既定`企業名`）/ `--corp-col`（既定`法人番号`）。

## 5. 検証結果（2026-07-06・本番データ）

本番3ソース（禁止7,070／既存顧客／SFリード86,673）での実行。既存顧客の照合範囲で2案:

| 案 | 既存顧客ソース | 禁止 | 既存顧客 | SF | 重複除外(ユニーク) | 被りなし |
|----|----------------|------|----------|-----|--------------------|----------|
| **A**（`dedupe`） | 送付CSVのみ（社名428） | 83 | 11 | 855 | 884（46.5%） | **1,018** |
| **B**（`dedupe:full`） | ＋`existing-bango.json`（法人番号1,387） | 83 | 95 | 855 | 909（47.8%） | **993** |

- 差の**84件**は、社名のみの送付CSVでは拾えず、**法人番号で捕捉した実在の既存顧客**（滋賀日野自動車・トナミ国際物流 等）。
- アプローチ禁止・既存顧客は「取りこぼす方がリスク」のため、既定は**安全側のB**を推奨。
- 収支検証: いずれも 被りなし＋除外＝母集団 1,902 で一致。

## 6. 既知の制約・改善余地

1. **母集団の法人番号充足率が 6.4%（122/1,902件）**、かつ既存顧客・SFの実データにも法人番号列が無いため、
   実運用の突合は**社名一致（推定）が主**。表記揺れは `normCompanyName` で吸収するが、
   同名異企業を巻き込む可能性が残る → `除外明細` の `突合確度=推定` を目視確認できるようにしてある。
2. SFレポートは会社名列 `会社名 / 取引先` のみで法人番号なし。将来SFに法人番号カスタム項目が入れば
   「確実」突合に格上げできる（列は自動判定するため追加設定不要）。
3. 既存顧客の照合範囲（案A/B）は運用ポリシー判断。`existing-bango.json` が現行の既存顧客と乖離する場合は
   Aに切り替え可（`npm run dedupe`）。最新の名前付き既存顧客CSVに一本化するのが理想。
