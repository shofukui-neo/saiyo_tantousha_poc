## 1. 改訂版リスト作成条件（ハードルール＝母集団の出入り）

スコアで上下させる“嗜好”ではなく、**入れる／落とすを決める硬い条件**。実装は [`src/icp-rules.js`](../src/icp-rules.js) に集約。

| 条件 | 値 | 根拠（実測） |
|--|--|--|
| **① IT・ソフトウェア 絶対除外** | 業種にIT/ソフト/情報処理/受託開発/インターネット/ゲーム/SIer 等を含む行を落とす | ソフトウエア6.2%・情報処理7.1%・インターネット2.0%。温かい経路でも13%止まりで**全業種最下位＝経路非依存の唯一の構造ルール（H4）** |
| **② 従業員数フロア** | **100名以上**（有効100-2000／スイート300-500） | <100名は成約率<14%、50名未満<10%、20-30名<7%。300-500=24%がピーク |
| **③ 新卒採用フロア** | **年6名以上** | 1-2名=3.6%（不毛）・3-5名=13%（中）・**6名以上=26%へ急伸**。6-30名が最良帯 |
| （従来どおり）既存顧客・NG・アーカイブ除外 | 勝ち済み/アプローチ禁止/死に筋を除外 | — |

> ①②③は env で調整可（`ICP_EXCLUDE_IT` / `ICP_EMP_MIN` / `ICP_HIRE_MIN`）。既定は分析結論。
> **不明(null)の軸ではフロアで落とさない**（判明していて下回る行だけを弾く＝データ欠損で母集団を痩せさせない）。

## 2. 改訂版スコアリング・ロジック（4軸の掛け算）

母集団に残った企業を、実コンバージョン率(lift)の掛け算で**成約見込み(propensity)**にランク付けする。

```
成約見込み ≈ 全体17% × lift(経路) × lift(業種) × lift(規模) × lift(採用人数)
```

前回まで欠けていた **lift(経路)＝第4軸** を先頭に足したのが本質。実装は [`src/channel-temp.js`](../src/channel-temp.js)＋[`scripts/build-lookalike-list.js`](../scripts/build-lookalike-list.js)。

### 第1レバー：経路の温度（lift 実測 / 最大の振れ幅）
| 経路クラス | 成約率 | lift | 意味 |
|--|--|--|--|
| **アウトバウンド架電** | **30.1%** | **1.77x** | 人が名指しで架ける＝本リポジトリの弾込め（**主動線化すべき／H5**） |
| 未タグ(温/手入力) | 21.4% | 1.26x | リスト名なし＝温かい/手入力/古参 |
| その他タグ | 20.7% | 1.22x | — |
| お断り再利用 | 8.6% | 0.50x | リサイクル |
| **コールド媒体一括** | **7.2%** | **0.42x** | マイナビ/リクナビ年度リストの一括インポート（低品位・大量） |

振れ幅 **30.1÷7.2 = 4.2倍**。業種(〜3x)・規模(〜1.5x)を上回る第1レバー。
→ firmographic だけのスコアは、**コールド由来(0.42x)を温かいリード(1.26x)と同点に扱い過大評価していた（H2）**。第4軸で是正。

### 第2〜4レバー（従来軸・lift 実測）
- **業種**：細分ラベルで持つ（[発見1](mochica-icp-v2-detailed.md)）。流通・小売・物販40%／金融・保険35%／介護31%／メーカー機電30%／商社26% が上位。スーパー/信金/機械/化学 等の低成約細分は lift<1 で自然に沈む。
- **規模**：300-500=1.41x をピークに 100-2000 の逆U字。
- **採用人数**：6-30名=1.5x台の台地。

## 3. 提案プラン振り分け（tier routing＝仮説H6）

規模帯で**提案プラン/セグメント**を出力列に付与し、単価を規模で当てにいく。実装は `proposalTier()`（icp-rules.js）。

| 従業員 | セグメント | 提案プラン | 狙い |
|--|--|--|--|
| <100名 | 対象外(小) | — | フロア未満で除外 |
| 100-500名 | **主戦場(スイート)** | ミニマム/ミドル | 成約率19-24%の本命。件数を取る |
| 500-1000名 | 有効(中堅上) | **スタンダード提案** | 成約率22%。単価を上げる |
| 1000-2000名 | 有効(上限) | スタンダード提案 | 競合ATS要確認 |
| 2000名超 | 要注意(大) | 競合ATS確認 | 自前/競合ATS濃厚（上限の敵は“不要”でなく“導入済み”） |

## 5. ハーベスト（候補生成）側への適用

同じハードルールを**弾込め段階**にも効かせる（[`src/mochica-fit.js`](../src/mochica-fit.js) の1件採点に統合済み）：

- **IT絶対除外**：`scoreMochica` が IT業種を検知したら total を強制フロア(≤12)に沈める。従来の -12 は強intentで打ち消され上位に浮上しえたが、これを絶対ルール化（`flags.hardExclude`）。
- **提案プラン**：全レコードに `segment`/`plan` を付与。
- **マイナビ収集フィルタ（ユーザー指定）**：マイナビページから拾う時点で**採用人数6名以上・従業員100名以上**をフロアに（`passesIcpFloor`）。
- **母集団の傾斜（H3）**：現行は製造・建設偏重（＝マイナビ掲載を手当たり次第に架電した影）。効率業種（流通・金融・介護・メーカー機電・商社）へ配分転換すると、同じ架電数で成約2倍が見込める（＝未開拓であって飽和ではない）。

## 5.5. 呼べる名指しリストの「3絶対条件」と採用数エンリッチ（2026-07 追補）

弾込め（架電）に載せる最終リスト＝`leads-mochica-named-consolidated.csv` は、**3つを絶対条件**にした
（[`src/build-named-consolidated.js`](../src/build-named-consolidated.js) が `qualifiesForList` で判定）。名指し架電(30.1%)は最良経路なので、
「名指しで・電話で・本気の採用枠に」架けられる相手だけを載せる。

| 絶対条件 | 判定 |
|--|--|
| **① 採用担当者名あり** | 氏名検証OKのみ（従来から） |
| **② 電話番号あり** | 空は除外 |
| **③ 年間新卒6名以上** | 判明かつ≥6。**不明は落とさず「採用数エンリッチ待ち」へ退避**（ユーザー指定） |
| （＋ 非IT・従業員100名以上） | 前掲ハードルールを継承 |

### 採用数が「不明」な企業の埋め方 ── マイナビ 採用データ（各募集コース面）
採用予定人数はマイナビ「前年度採用データ(employment.html)」から各**募集コース(displayEmployment)**の
「募集人数 X〜Y名」を辿り、**全コースの下限を合計**して年間新卒採用予定を出す（[`src/scrape-mynavi.js`](../src/scrape-mynavi.js) の
`scrapeHireByName`／`extractHireOnPage`／`sumHireCourses`）。実測でマイナビは職種ごとにこの数字を持つため、
未エンリッチの担当者名リードでも採用数を後から確定できる。

```
出力の3分岐:
  3絶対条件クリア        → leads-mochica-named-consolidated.csv（呼べる）
  担当者名+電話あり/採用数不明 → data/leads-mochica-named-need-hire.csv（エンリッチ待ち）
  電話なし/IT/採用<6/従業員<100 → 除外（内訳をログ）

パイプライン:
  node src/build-named-consolidated.js                 # 3絶対条件で分岐、エンリッチ待ちを書き出す
  node scripts/enrich-hire-from-mynavi.js \             # 待ち行列の採用数をマイナビで確定
       --in data/leads-mochica-named-need-hire.csv --out data/hire-enriched-mynavi.csv
  node src/build-named-consolidated.js                 # 採用数を反映し、6名以上を呼べるリストへ昇格
```

`build-named-consolidated.js` は `data/hire-enriched-mynavi.journal.json`（全処理を累積・キー=企業名）を
自動で取り込むため、**エンリッチ→再統合**を回すほど「採用数不明」が減り、呼べるリストが太る。
※出力CSVでなく journal を読むのは、キューから昇格した過去の成功を取りこぼさない（再統合で冪等）ため。

### 実績（2026-07 初回）
| 分岐 | 社数 |
|--|--|
| **3絶対条件クリア（呼べる）** | **273**（今週架電259／ナーチャ14） |
| 採用数エンリッチ待ち | 156 |
| 絶対条件で除外 | 1,663（電話なし855／採用<6 504／従業員<100 294／IT 10） |

エンリッチ対象170社のうち採用数を確定できたのは14社（うち6名+ が9社＝全て呼べるリストへ昇格）。
残りは**マイナビ非掲載20社／採用データ未公開133社**＝マイナビ側にデータが無く、抽出の失敗ではない
（例: アート梱包運輸の employment.html はHTTP200だが328文字＝データ空）。非掲載・未公開の多くは
recruiter/Wantedly由来（技術系ソース）で、「ITは構造的に不適(H4)／収集をマイナビ効率業種へ寄せるべき(H3)」を裏づける。

## 5.6. サプレッション層（N層）── 負のシグナルで「純損失架電」をゼロに（2026-07 追補）

252件の架電アウト分析（約30-35%は架電前に判定可能）を受け、正のICP/類似スコアに欠けていた
**負のシグナルで除外/降格する層**を追加した（[`src/suppression.js`](../src/suppression.js) → [`src/build-named-consolidated.js`](../src/build-named-consolidated.js)）。
データ源は既存架電CRM **BALESCLOUD**（会社名で法人JOIN）。既存お断り・商談中・失注への重複架電＝
アポにならずブランドを毀損する「純損失架電」を母集団から抜く。

| N | ルール | データ | 動作 |
|--|--|--|--|
| **N1** | 商談中/既存（商談あり×失注なし） | BALES商談 | 除外→既存営業へ連携 |
| **N2** | 過去お断り（冷却窓<12ヶ月） | BALESコール結果「担当者接触：お断り」6,663件 | 除外（クールダウン） |
| **N3** | 失注（冷却窓<12ヶ月）／冷却明けは降格 | BALES失注日 4,266件 | 除外 or 降格 |
| **N-dead** | 電話不通（番号不備/使われていない） | BALESコール結果 | 除外 |
| **N7** | 公的セクター（官公庁/自治体/公社） | 業種 | 降格（LINE利用制限の蓋然性） |
| ~~N4~~ | ~~採用ボリューム薄~~ | — | **絶対条件③(採用6名+)で代替済み＝未使用**。単一数値"6"はSFバンド下限で真の少人数でない |

**効果（BALES照合20,494社）**: 呼べる273社のうち **47社を除外**（商談中5・お断り冷却中26・失注冷却中26・不通3＝コード重複含む）、
**12社を降格**（冷却明けの再架電候補は末尾へ）→ 呼べるリストは **226社（クリーン214＋降格12）** に純化。
除外された中には旧スコア上位（例: 商談中の(株)カーク＝旧#5）も含まれ、**高ICP適合だが純損失**の架電を正しく抜けている。
除外先: `data/leads-mochica-named-suppressed.csv`（抑制コード・理由つき）。

> **重要な補正（実データで旧仮説を却下）**:
> - 分析の「N7=金融もLINE制限で降格」は採用しない。**金融・保険は実測で成約35%＝勝ち筋**のため、公的セクターのみに限定した。
> - §3「採用ボリューム条件（採用2-3名を外す）」は**絶対条件③（採用6名以上）で既に達成済み**。採用予定人数の単一数値はSFバンドの下限表記のため、降格判定には使わない。
>
> **リストで防げない残り（G層の仕事）**: 現状満足(~15%)＋競合充足(~13%)は架電前に判定不能で、リストでは消えない。
> リスト改善は「分母の質」、G層改善は「条件付き確率」の両輪（この改訂だけで転換率5%には届かない、は分析どおり）。
> 未実装の高度シグナル: N5(親会社グループ採用一元化=gBizINFO)・N6(競合ATSフィンガープリント=採用ページ巡回)は外部データ/新規開発が必要。

## 7. 知的誠実性（限界）

- **「未タグ＝温かい」は近似**。出所不明の古参レコードも含む。ただし 経路の単調勾配（架電>未タグ>お断り>コールド）と業種序列の経路またぎ一貫性から、経路効果は頑健と判断。
- **現顧客スナップショット＝解約(churn)が見えない**。「効率業種＝高継続」かは有料終了実績を含む履歴で要検証（一致しなければLTV前提が崩れる）。
- **クリーンな決着は実験**：同一の300-500名・流通企業群を「コールド一括」vs「名指しアウトバウンド」で無作為割付し成約率差を測る。
- 経路lift は**既存リードの獲得経路**に基づく。名指し架電で再アプローチすれば温度が上がりうるが、コールド由来は firmographic を揃えても低成約が持続するため、down-weight は妥当。
