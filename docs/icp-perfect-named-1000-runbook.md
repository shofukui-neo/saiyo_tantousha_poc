# ICP完全適合 × 採用担当者名判明 × かぶりなし 1000件リスト — ランブック

ユーザー指定（2026-07）:「ICP完全適合かつ、採用担当者名の判明している、かぶりのないリストを1000件作成」。

## 成果物
- **`data/leads-icp-perfect-named-1000.csv`**（1000社・31カラム・架電できる順）
- 生成: `npm run icp:perfect`（= `node src/build-icp-perfect-1000.js`・ネットワーク不要・冪等）

## ICP完全適合（検証済）の定義 — 6条件をすべて“実データ”で満たす
| # | 条件 | 実装ゲート |
|---|------|-----------|
| ① | かぶりなし | 統合マスタの `既存被り` 列が空（BALES/MOCHICA顧客/SF全リードに不在） |
| ② | 担当者名判明 | `採用担当者名` 非空 ＋ 品質ゲート `cleanCrossRefName`（連結/ふりがな/住所断片/1文字を除外） |
| ③ | 新卒インテント | `scoreMochica.flags.verifiedIntent`（新卒フラグ or 新卒媒体掲載を実取得） |
| ④ | 規模フィット | `従業員数` 判明かつ **100〜2000名**（実成約率の有効域＝scoreSize 88-100） |
| ⑤ | 非IT | `isExcludedIndustry` が false（IT/ソフト＝成約率6%は絶対除外） |
| ⑥ | 到達性 | `電話番号` が妥当（`scoreMochica.flags.callable`） |

現行 MOCHICA アポ取得期待値モデル（`src/mochica-fit.js`）で**再採点**し、アポ期待度降順で上位1000社を確定。

## 実測（2026-07 時点）
- 統合マスタ 30,290 → かぶりなし 15,594 → ＋担当者名 4,753 → 品質ゲートで30社除外 → **完全適合候補 1,305社** → 上位 **1,000社**（バッファ305社=30%）。
- 確定1000社の実測: アポ期待度 平均86/最小80（全社 `今週架電`）、**従業員数100%判明**（100-299=527/300-500=246/501-1000=227・全社100-1000名）、電話100%、担当者名100%、採用予定人数 判明776、メール470。
- 担当者名の質: **966/1000 が非「代表」の部署/役職つき実担当者**（代表者名フォールバックは6社のみ）。母集団はマイナビ問合せ先由来が主で、個人名の裏取りが効いている。

## 設計上の判断（なぜこの定義か）
- 「完全適合」は**代理推定でスコアが嵩上げされた社を排除**するため、③〜⑥を実データ充足で要求。上位1000社が検証済みシグナルで完全適合だと言い切れる。
- 規模は理想スイート300-500名だけだと1000に届かないため、**実成約率の有効域100-2000名**（scoreSize≥88）を採用。結果は全社100-1000名に収束。
- 年間新卒6名以上（`qualifiesForList` の hire フロア）は `採用予定人数` の充足率が低く1000規模で両立不能。新卒媒体掲載インテントで代替し、判明社は `採用予定人数` 列で明示（776社）。

## 母集団の上限
完全適合候補は1,305社が現データの上限。1000超の増量や条件をさらに厳格化（例: hireフロア必須）する場合は、[[named-mochica-max-list]] の「拡張キーワードでマイナビ再走→統合→再採点」で母集団を広げる必要がある。関連: `docs/mochica-icp-refresh-2026-07.md`, `docs/mynavi-recruiter-name-skill.md`。
