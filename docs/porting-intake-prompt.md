# 移植先ヒアリング・プロンプト（そのまま貼って使う）

> 使い方：以下を、移植先アプリを知る人（開発者）または移植先コードベースを読めるAIに貼り付けて回答を得る。
> 回答が揃えば「G-Chain OS 別アプリ移植ロードマップ(docs/g-chain-os-porting-roadmap.md)」の Phase 3 以降を確定できる。

---

## ここから貼り付け ↓↓↓

私は「G-Chain OS」という営業テレアポ分析システムを、別のアプリへ移植しようとしています。
移植方針を確定するため、移植先アプリについて以下を回答してください。**不明な項目は「未定」で構いません。**

### 背景（このシステムが何か・30秒で）
- 通話音声を **左ch=自分/右ch=相手のステレオで録音**→各chを別々に文字起こし→話者確定。
- そこから客観指標（talk比・質問数・打診有無・冒頭の掴み・独白時間・反論数）を算出し、
  架電直後にGOOD/MORE/次NGのフィードバックを返し、蓄積して「自分の弱み」を可視化する。
- 加えて、通話履歴の構造化データから「誰にいつ架けるか」をスコアリングする層もある。
- 設計は **Ports & Adapters**：分析ロジック（コア）は不変で、録音・文字起こし・保存・LLM・UI（アダプタ）を
  移植先の環境で差し替える。→ 下の質問は「各アダプタが移植先でどう実現できるか」を知るためのもの。

### A. 移植先アプリの基本
- A1. アプリ名／目的（何をするアプリか）
- A2. 言語・フレームワーク（例: TypeScript+React / Swift / Kotlin / Flutter / Go / Python 等）
- A3. 稼働プラットフォーム（Webブラウザ / デスクトップ(Electron等) / iOS / Android / サーバ/バックエンド）
- A4. 既存アーキテクチャ（SPA / モノリス / マイクロサービス / ローカルアプリ 等）
- A5. **localhostで常駐サービス（サイドカー）を動かせる環境か**（はい/いいえ）※別言語移植の選択肢に直結

### B. 録音（Capture アダプタ）
- B1. 通話音声はどこから取れるか（アプリ内ソフトフォン / 電話SDK(Twilio/Amazon Connect等) / PCシステム音声 / 端末録音 / その他）
- B2. **自分と相手を別々（2ch/ステレオ）で取れるか**（はい/いいえ/不明）※話者分離の要。取れないなら相手・自分は混ざる
- B3. 音声はリアルタイムで取得できるか、それとも通話後のファイルのみか
- B4. 音声フォーマット・利用可能な録音API（wav/mp3 / MediaRecorder / AVAudioEngine / 端末API名 等）

### C. 文字起こし（STT アダプタ）
- C1. 使えるSTTは何か（オンデバイス / クラウド名(OpenAI/Google/Azure/Deepgram等) / whisper / なし）
- C2. リアルタイム（ストリーミング）文字起こしは可能か（はい/いいえ）※架電中コーチングの前提
- C3. 話者ダイアライゼーション機能はあるか（はい/いいえ）※B2でステレオが取れれば不要
- C4. 日本語の精度・レイテンシ要件（例: 精度重視 / 速度重視 / どちらも）

### D. 蓄積（Storage アダプタ）
- D1. 通話レコードの保存先（ブラウザIndexedDB / SQLite / ファイル / クラウドDB名 / その他）
- D2. 単独利用か、マルチユーザー/チーム（複数営業）か ※弱み蓄積の集計単位・認証に影響
- D3. 既存の通話履歴・リード/顧客データはあるか。あればスキーマ概要（項目名）を数行で

### E. LLM 診断（任意アダプタ）
- E1. 使えるLLMはあるか（Claude / OpenAI / ローカルLLM / なし）
- E2. アクセス方法（API/SDK/社内ゲートウェイ）と、通話テキストを外部に送ってよいか

### F. UI・体験
- F1. 分析結果の表示形態（既存画面への埋込パネル / 専用画面 / 架電中のリアルタイムオーバーレイ）
- F2. **架電中のリアルタイムコーチングは必要か**、それとも架電後フィードバックのみで良いか
- F3. 既存のUIフレームワーク／デザインシステム（あれば）

### G. 移植スコープ
- G1. 移植したいのはどれか：①音声分析(v2.1) ②構造化スコアリング(v2.0) ③弱み蓄積 ④全部
- G2. まずMVP（架電後フィードバック＋蓄積）か、最初からフル（架電中コーチング含む）か
- G3. **別言語の場合**：コア(分析ロジック)を移植先言語で再実装できる開発体制はあるか、
      それともJS/コアをそのまま埋め込みたいか（サイドカー/WASM）

### H. 制約・ポリシー
- H1. 音声・文字起こしを端末外（クラウド）へ送ってよいか（PII/個人情報保護・社内コンプラ）
- H2. オフライン動作は必須か
- H3. レイテンシ／端末性能の制約（モバイルGPU有無、CPU等）
- H4. 目標時期・期限

### 回答フォーマット
- 各項目に1〜2行で回答（未定は「未定」）。
- 最後に必ず1文で：**「最優先で動かしたい1シナリオ」**（例：「iOSアプリで、通話後に自動で弱みフィードバックを出したい」）。

## 回答が来たら私がやること（対応表）

| あなたの回答 | 確定する移植方針 |
|---|---|
| A2/A3 が Node/JS・ブラウザ | コアをnpm/vendorでそのまま import（労力: 小） |
| A2 が別言語 かつ A5=はい | **サイドカー**：server.jsをコアAPIに純化しHTTPで呼ぶ（言語不問・労力: 中） |
| A2 が別言語 かつ A5=いいえ（モバイル等） | コア再実装(G3体制あり)＋golden vector、またはWASM埋込 |
| B2=いいえ（話者分離不可） | モノラル→LLM事後帰属の分岐を実装（attributed=false経路） |
| C2=いいえ | 架電中コーチングは不可→架電後フィードバックに限定（MVP優先） |
| H1=不可 | STT/LLMをオンデバイス（whisper/ローカル）に固定 |

これらが埋まれば `contracts/`（データ契約とgolden vector）を切り出す **Phase 0** に即着手できます。
