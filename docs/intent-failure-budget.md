2026-09-18 追加。インテント（層2）に、

- **昨年度の採用失敗**（S22〜S25 / `src/intent/failure-signals.js`）
- **採用にお金を出せるか**（S26〜S29 と資金リスク / `src/intent/budget-signals.js`）

の2系統を足した。軸は 21 → **29** になった。

---

## なぜこの2つか

これまでの層2は「いま採用面に何が書いてあるか」だけを見ていた。二次募集（S2）も
採用数増（S4）も、**昨年度うまくいかなかったことの“結果”**であって、原因そのものではない。
原因を名指しできると、架電の1行目が変わる。

> 「昨年度の新卒採用は、計画に対してどのくらい充足されましたか」

もうひとつ、担当者が乗り気でも決まらない理由がほぼ一択で出ていた
——**会社の方針としての無駄の削減**。だから「採用にお金を出せる会社か」を先に見て、
出せない会社は今期の商談ではなく**検討時期を押さえてナーチャリング**に回す。

## S22〜S25 昨年度の採用失敗

| 列 | 軸 | 重み | 半減期 | 判定 |
|---|---|---|---|---|
| S22_昨年度未充足 | 昨年度の採用計画が未充足 | 36 | 210日 | 前年の**募集人数**（観測台帳）と**入社実数**（定着率欄）の差 |
| S23_早期離職 | 直近入社の早期離職 | 30 | 210日 | 定着率 ≤70% 確定／≤85% 強／≤92% 中 |
| S24_採用難の記載 | 採用難・計画未達の記載 | 28 | 90日 | 掲載文・自社サイトの文面（否定文は打ち消す） |
| S25_入社数減 | 新卒入社数の減少 | 22 | 210日 | 入社実数の前年比（15%未満かつ3名未満の減少は採らない） |

群上限 **44**（4軸は同じことの別の言い方なので、最大重み1本＋補強1本ぶんに抑える）。

### S22 が「確定」になる条件

**前年の計画が要る。** 計画（募集人数）は掲載面から消えるので、観測台帳
（`data/intent/observations.json` の `卒年面[卒年].募集人数`）に残っている社だけが確定になる。

- 台帳あり → `昨年度の入社実数 ÷ 前年の募集人数` で充足率 → 60%以下なら最上位
- 台帳なし（1周目）→ 今年度の募集人数と昨年度実績を並べるだけ。**「中」か「弱」止まり**

つまり **S22 の本領は2周目から**。1周目で確定が出ないのは仕様。
26卒面のような過去の卒年面はマイナビ側で既に落ちている（2026-09 実測: `/26/` は本文709字のスタブ）ので、
過去に遡って計画を取り直すことはできない。

### A階層への単独昇格

`score.js` の `PROMOTE_SIGNALS` に `LAST_YEAR_SHORTFALL` を入れた。
**確定で立てば合計点に関わらずA**（従来は S1 人事中途求人だけ）。重みを水増しせず昇格条件として書いてある。

### 採れなかったのか、絞ったのか

公開情報では区別できない。だから S25 の根拠文には必ず
「採りきれなかったのか計画を絞ったのかは架電で確認」と書き、トークも両論で聞く形にしてある。

## 資金リスク（点にしない）

「お金がない」を4つに割る。`budget-signals.assessFunding(ev, hits)`。

| 状態 | 中身 | 係数 | 次の一手 |
|---|---|---|---|
| 逼迫 | 赤字・営業損失・減収減益／希望退職・店舗閉鎖・事業撤退 | 0.70 | 新規予算ではなく**費用の振替**で提案 |
| 逼迫 | 採用見送り・募集停止・採用人数を絞る（募集人数の前年比減も含む） | 0.75〜0.80 | 同上。時期を押さえる |
| 予算確定 | 今期予算は確定／来期・次年度の予算で検討 | 0.85 | **検討時期を聞いてナーチャリング** |
| 余力あり／中立 | S26〜S29 が立っている／記載なし | 1.00 | 「何にどれだけ使っているか」をヒアリング |

**リスクは加点しない。** 加点側と同じ土俵に置くと「リスクが多い会社ほど点が高い」になる。
インテントスコアはそのまま（シグナルは実際に立っているので事実は曲げない）、効かせるのは2か所だけ:

1. `総合優先度 = (スコア×0.65 + アポ期待度×0.35) × 予算係数`（`target-fit.js`）
2. `推奨アクション` → A階層以外は「ナーチャリング（〈状態〉／検討時期〈時期〉を確認）」（`score.js`）

A階層を落とさないのは、階層がタイミングの話だから。資金が閉じていても、いま採用が破綻している社には架ける。
そのとき読む文は `予算トーク` 列にある（「新規のご予算ではなく、いま媒体や代行にかけている費用の一部を振り替える形で…」）。

### 検討時期

`extractTiming()` が「来期／下期／上期／期初／N月」を**検討・予算の文脈の近くにある時だけ**拾う。
「4月入社の新卒を募集中」は拾わない。取れたら `検討時期` 列に入る。

## 出力される列

既存に加えて:

- 資金: `予算状態` `予算係数` `資金リスク` `検討時期` `予算トーク`
- 素の数字: `昨年度入社数` `昨年度定着率` `定着率(3年)` `売上高` `従業員数(掲載)` `拠点数` `都道府県数` `上場区分` `特徴タグ`
- シグナル列: `S22_昨年度未充足` 〜 `S29_原資規模`

素の数字はシグナルが立たなかった社でも架電の材料になる
（「昨年8名採って3名辞めています」は、それ自体が話の入り口になる）。

## 未了: 階層の閾値の較正

`score.js` の `TIERS` の **A ≥ 45.4 は21軸時点の分位のまま**。29軸では目盛りが伸びているので、
較正するまで A の件数は従来より膨らむ（有望企業が増えたわけではない）。

新軸の一次情報（定着率・会社データ・事業所・特徴タグ）は過去の取得回では集めていないため、
**`npm run intent:rescore` では較正できない**。順番は:

```
npm run intent:wide          # 29軸ぶんの一次情報を取り直す（--resume で継続可）
# 全数・群上限適用後のスコア分布から A が上位約10%になる値を取る
# score.js の 45.4 を差し替え
npm run intent:rescore
```
